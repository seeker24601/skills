# Analyze

Use for understanding a business, product, market, person, team, or situation.

1. Bound the subject, time horizon, and question the assessment should answer. Separate supplied facts from interpretations and missing context.
2. Load `business-analysis` for commercial structure, performance, financial statements, or strategy. Load `people-and-incentives` for behavior, organizations, or strategic interaction. Combine them only when both explain a material part of the question.
3. Load `game-theory` when the outcome depends on other actors responding to each other. Use `research-and-fact-check` for external claims that determine the conclusion. Weigh rival explanations and counterevidence without manufacturing equal sides.
4. Synthesize what holds up, what remains uncertain, and which observation would change the assessment. Use `workflows/evaluate.md` if options or probabilities are requested. An assessment does not automatically authorize recommendations to be executed.
5. Answer at the requested depth with traceable evidence. Preserve ambiguity rather than replacing it with confident labels. Save sensitive personal analysis only with explicit consent to content and destination.
