# Prototype

Use for demos, proofs of concept, experiments, and fast first versions. Follow the user's requested standard; a production requirement takes precedence over a preference for speed.

1. Identify what the user should be able to try and what the experiment should prove. Read project instructions and locate the existing implementation owner.
2. Load `quick-build` to choose a small complete path, implement it, and verify it. Let that method govern scope cuts and shortcuts; ordinary conversation needs no workflow.
3. Use available subagents for bounded independent work only when it saves time. Keep shared writes coordinated and verify their contributions together.
4. If existing behavior fails, route that part through `workflows/debug.md`. If the task requires production hardening or a broader implementation, use `workflows/build.md`. Do not quietly lower explicit requirements.
5. Deliver the working preview or artifact, what it proves, and its material limitations. Let the user's feedback determine the next iteration.
