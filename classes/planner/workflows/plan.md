# Plan

Use when asked to plan, scope, sequence, or prepare work before implementation.

1. Read the request, project instructions, and existing system. Identify the outcome, constraints, owner, and decisions that materially change the plan. Record assumptions and ask only for necessary missing decisions.
2. Load `acceptance-criteria`. Define what completion will look like and the checks that will establish it.
3. Choose the smallest coherent approach. Record scope and exclusions, ordered steps, dependencies, execution owners or proposed roles, risks, and recovery needs. Mark proposed assignments as unconfirmed. Place checks alongside the steps they verify.
4. Challenge the weakest assumption and most consequential failure path. Use a separate bounded reviewer when available and worthwhile; otherwise label this a self-review. Resolve findings or record the outstanding decision before handoff.
5. Deliver a plan whose requirements have stable labels and whose version can be identified by its saved revision or the exact message. Write a file only when requested or appropriate to the authorized task. Name the next action without starting implementation merely because the plan is complete.
